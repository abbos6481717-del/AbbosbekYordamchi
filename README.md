# Telegram Business personal assistant

A bot that connects to your personal Telegram account through **Telegram Business → Chatbots**.
When someone writes to you, it drafts a reply in your name and in your style, using what you
wrote about yourself in `profile.md`.

Replies are generated by the **Claude Code CLI** (`claude -p`) installed next to the bot, so your
Claude **subscription** is used. An Anthropic API key is never used.

## What it does

- **PREVIEW mode is the default** (`AUTO_SEND=false`): drafted replies are only shown in the logs
  (a `PREVIEW, not sent` block) and appended to `data/previews.jsonl`. Nothing is sent until you set
  `AUTO_SEND=true`.
- **Which chats the bot sees is decided only by Telegram**: *Settings → Telegram Business →
  Chatbots* lets you choose the chats. There is no allowlist in the code.
- It answers in the language of the other person's latest message (Uzbek in the same script,
  Russian or English), never agrees to money/debts/meetings/plans, and never shares addresses,
  cards, passwords or codes.

### Behaviour

| Situation | What happens |
|---|---|
| Business connection of another account | Ignored, a warning is logged, Claude is not called |
| Which chats | Whatever you selected in Telegram's *Business → Chatbots* settings |
| You write in a chat yourself | Saved to history, never answered; the bot stays quiet in that chat for `OWNER_TAKEOVER_MINUTES` (default 15) |
| Messages from bots / the bot's own replies | Ignored (`sender_business_bot`, `is_bot`) |
| Duplicate update | Processed once, also after a restart (`data/seen.json`) |
| Service messages (title changed, pins, ...) | Ignored; stickers, voice, photos etc. are described as `[sticker] 😀`, `[voice message]`, ... |
| `/pause` | No replies until `/resume`; survives restarts |
| Claude subscription usage limit | No Claude calls until the reset time (or `LIMIT_COOLDOWN_MINUTES`); survives restarts; the owner gets a message in auto-send mode |
| Timeout / login error | Logged; nothing is sent to the chat; in auto-send mode the owner is told at most once per 10 minutes |
| Claude answers `[SKIP]` | Nothing is shown or sent |
| Before every auto-send | Pause/limit/takeover are checked again and the business connection is fetched fresh from Telegram (owner, enabled, `can_reply`) |

### Owner commands (private chat with the bot)

| Command | Effect |
|---|---|
| `/start` | Uzbek instructions: current mode and state, how to connect (Chatbots), commands |
| `/pause` | Stop replying |
| `/resume` | Resume; also clears the usage-limit wait and takeover timers |
| `/status` | Mode, state, limit, number of chats in history |

Anyone else who sends `/start` gets a short Uzbek note that this is a personal assistant and they
should write to the owner directly. Claude is not called and nothing about the owner is revealed.
All other messages from other people to the bot are silently ignored.

## How Claude is called

One `claude -p` run per reply, started with `asyncio.create_subprocess_exec` (never a shell):

```
claude -p --safe-mode --settings '{"disableAllHooks": true, "enabledPlugins": {...: false}}'
       --tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands
       --no-session-persistence --system-prompt-file <0600 temp file>
       --output-format json --effort low [--model ...]
```

- No tools, MCP servers, hooks, plugins (every built-in plugin is disabled by name), skills, slash
  commands, CLAUDE.md or auto-memory.
- **`--bare` is not used**: it ignores the OAuth login, so the subscription would not work.
- The conversation goes through **stdin only**; the system prompt with your profile is in a 0600
  temp file (deleted afterwards), so neither shows up in `ps`.
- Each run gets its own empty 0700 working directory under `data/claude-run`, its own process
  group, and is killed (with any children) on timeout.
- The child environment is a copy of the bot's with all `ANTHROPIC_*`, `TELEGRAM_BOT_TOKEN`,
  `CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY`, `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` and
  `CLAUDE_CODE_SIMPLE` removed, plus `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and
  `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`. `CLAUDE_CODE_OAUTH_TOKEN` is added only when configured.
- **Token rules**: `CLAUDE_CODE_OAUTH_TOKEN` must be a `claude setup-token` token (`sk-ant-oat...`).
  API keys (`sk-ant-api...`) are rejected. The token is never printed: it is hidden in `repr`,
  replaced by `[REDACTED]` in CLI output, and config errors never echo it.
- `python bot.py --check-claude` sends a tiny request and fails (exit code 1) unless tools, MCP
  servers, plugins and skills are all empty and no API key is used.

## Deploy to Railway

1. On a computer with a browser run `claude setup-token` and approve with your subscription
   account. You get a `sk-ant-oat...` token valid for 1 year.
2. In @BotFather: `/newbot`, then *Bot Settings → Business Mode* → turn on. Get your numeric
   user ID from @userinfobot.
3. Create a **private** GitHub repository and push this code (`profile.md` goes into the Docker image).
4. Railway → *New Project* → *GitHub Repository* → select the repository.
5. Service → *Variables* → *Raw Editor*:
   ```
   TELEGRAM_BOT_TOKEN=...
   OWNER_ID=...
   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
   AUTO_SEND=false
   ```
   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`, `LIMIT_COOLDOWN_MINUTES`,
   `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`. Not needed: `CLAUDE_BIN`, `DATA_DIR`, `PROFILE_PATH`.
6. Volume: right-click the canvas (or Cmd/Ctrl+K) → *Volume* → select the service → mount path
   exactly **`/app/data`** → *Deploy*. Without a volume, history, pause and limit state are lost on
   every deploy.
7. Logs should show `Bot @... is running`, `Mode: PREVIEW` and
   `Claude auth: subscription token from environment variables`. Red lines in Railway are just
   stderr, not errors.
8. Send `/start` to your bot, then in Telegram *Settings → Telegram Business → Chatbots*
   (Telegram Premium required): enter the bot username, choose the chats, allow replying.
   The log shows `Business connection ...: user=<id> enabled=True`.
9. When someone writes to you, a `PREVIEW, not sent` block appears in the logs. When you are happy
   with the drafts, set `AUTO_SEND=true`.

Notes:

- Run the bot in **one place only**: two pollers with the same bot token interfere. Do not run
  `python bot.py` locally while Railway is running.
- Every push redeploys. Changing `profile.md` also means commit + push.
- If the Claude token expires or leaks: run `claude setup-token` again and update the Railway
  variable. If the bot token leaks: `/revoke` in @BotFather.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt        # Windows: .venv\Scripts\pip ...
cp .env.example .env && chmod 600 .env                # Windows: Copy-Item .env.example .env
# put the claude setup-token token into .env with an editor (one line)
.venv/bin/python bot.py --check-claude
.venv/bin/python bot.py --try "Salom, qalesan?"
```

If `CLAUDE_CODE_OAUTH_TOKEN` is empty, this machine's own `claude` login is used (local testing
only). In local mode only `.env` is read; variables exported in your shell are ignored.

On Windows install the native Claude Code (`claude.exe`, e.g. `irm https://claude.ai/install.ps1 | iex`);
an npm `claude.cmd` shim is refused because it would run through `cmd.exe`.

## Commands

| Command | Purpose | Exit codes |
|---|---|---|
| `python bot.py` | Run the bot with settings from `.env` | 0, 2 = config error or bot token rejected |
| `python bot.py --settings-from-env` | Container mode (Railway): settings from environment variables, removed from the process environment right after reading | same |
| `python bot.py --check-claude` | Check the Claude CLI setup, no Telegram | 0 ok, 1 check failed, 2 config error |
| `python bot.py --try "text"` | Draft a reply to a made-up message, no Telegram | 0 ok, 1 Claude error, 2 config error |

`--check-claude` and `--try` do not need the Telegram settings and also work with `--settings-from-env`.

## Tests

```bash
.venv/bin/python -m pytest
```

All tests run offline: a recording fake Telegram session and a fake `claude` executable (the CLI
tests need POSIX and are skipped on Windows).
